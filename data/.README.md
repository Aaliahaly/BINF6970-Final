# TCGA LGG Multi-Omics Data Availability and Workflow Stages

This directory documents the external datasets used and generated in the TCGA Lower Grade Glioma multi-omics database project.

The project data files are hosted externally on Figshare because several files are too large to store directly in GitHub.

Each Figshare dataset represents a specific stage of the workflow, starting from the original TCGA LGG source files and ending with final harmonized datasets, SQL database files, and Neo4j graph database files.

## Purpose of This Directory

This directory acts as the data access and workflow-stage guide for the project.

It explains:

- Where the data files are hosted
- Which dataset belongs to each workflow stage
- Which files are used as pipeline inputs
- Which files are generated as intermediate outputs
- Which files represent the final harmonized datasets
- Which files support SQL database construction
- Which files support Neo4j graph database construction

The actual large data files are not stored directly in this GitHub repository.

---

## Overall Data Workflow

The project converts selected TCGA Lower Grade Glioma multi-omics source data into cleaned, validated, harmonized, database-ready, and graph-ready datasets.

The data workflow follows this order:

1. Original TCGA LGG source data
2. Selection of used and unused source files
3. Preparation of Python pipeline input files
4. Data cleaning and transformation
5. Dataset validation
6. Sample-level harmonization
7. Gene-level harmonization
8. HGNC-based gene identifier mapping
9. Final dataset harmonization
10. Final proof report generation
11. SQL database file generation
12. Neo4j graph database file generation

Stages 4 to 10 are executed by the core Python pipeline.

SQL and Neo4j files are generated through separate post-pipeline database implementation steps.

## Files Needed to Run the Core Pipeline

To run the core Python pipeline, download the pipeline input files from Figshare and place them in:

```text
data/Python_Pipeline_Input_Files/
```

Required files:

```text
Clinical&Sample(1).xlsx
data_cna.txt
data_mrna_seq_v2_rsem.txt
Mutation(1).xlsx
hgnc_complete_set.txt
```

Then run the pipeline from the project root directory:

```bash
python scripts/run_pipeline.py
```

The core pipeline generates the cleaned, validated, harmonized, HGNC-mapped, final harmonized, and final report outputs.

## Reproducibility Notes

The Figshare datasets preserve the complete data workflow.

A user can reproduce the project in two main ways:

1. Start from the pipeline input files and rerun the Python pipeline.
2. Use the final harmonized datasets, SQL files, and Neo4j files directly.

The first route supports full pipeline reproducibility.

The second route supports direct database reconstruction and graph database construction.

All large files are hosted externally so that the GitHub repository remains lightweight, readable, and version-control friendly.

## Summary

This `data/` directory provides the access map for all project datasets.

It links each Figshare dataset to its role in the workflow and explains how the datasets connect to the Python pipeline, SQL relational database, and Neo4j graph database implementation.

The final harmonized datasets support reproducible MySQL database population.

The SQL files support database reconstruction.

The Neo4j files support graph-based analysis of selected SQL-derived TCGA LGG mutation patterns.
