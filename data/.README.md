# Pipeline Overview

The pipeline converts selected TCGA LGG source data into cleaned, validated, harmonized, and database-ready datasets.

The workflow includes the following stages:

1. Data cleaning and transformation
2. Dataset validation
3. Sample-level harmonization
4. Gene-level harmonization
5. HGNC-based gene identifier mapping
6. Final dataset harmonization
7. Final proof report generation

---

# Python Pipeline Input Files

The input dataset contains the selected files used as starting material for the Python processing pipeline.

These files were prepared from selected source files from the original TCGA LGG dataset downloaded from cBioPortal. They provide the clinical, sample-level, mutation, copy number alteration, expression, and hypoxia-related information required for downstream processing.

The source files used to prepare the pipeline input files include:

- `data_clinical_patient.txt`
- `data_clinical_sample.txt`
- `data_clinical_supp_hypoxia.txt`
- `data_cna.txt.zip`
- `data_mutations.txt.zip`

These files are not the complete original TCGA LGG download. They represent the selected project-specific input files needed for the pipeline.

# 1. Data Cleaning and Transformation

This stage cleans and transforms the selected input files into structured datasets suitable for downstream validation, harmonization, and database construction.

## 1.1 Clinical and Sample Data Cleaning

| Item | Details |
|---|---|
| Input dataset | `Clinical&Sample(1).xlsx` |
| Output dataset | `Clinical&Sample.xlsx` |
| Script | `01_clean_clinical_sample.py` |
| Stage | Cleaning |

This script cleans and standardizes clinical and sample data into a structured format ready for analysis and database integration.

It renames variables into consistent database-aligned names, converts encoded survival variables into clear clinical labels, rounds time-related fields, standardizes cancer type and site naming, and extracts IDH status and 1p/19q codeletion status from subtype information.

It also filters and orders the dataset into a fixed schema to improve readability, visualization, and downstream database use.

Main changes include:

- Standardized all column names into database-friendly format.
- Renamed survival variables into clear clinical terms.
- Converted binary survival encodings into explicit clinical labels.
- Rounded survival time variables to two decimal places.
- Standardized cancer type and cancer site fields.
- Renamed histological classification fields.
- Split subtype information into `IDH_Status` and `Codeletion_Status`.
- Standardized hypoxia-related variables.
- Removed whitespace inconsistencies.
- Verified uniqueness using `Patient_ID` and `Sample_ID`.

## 1.2 Copy Number Alteration Data Cleaning

| Item | Details |
|---|---|
| Input dataset | `data_cna.txt` |
| Output dataset | `cna_long.csv` |
| Script | `02_clean_cna.py` |
| Stage | Cleaning |

This script transforms copy number alteration data from wide matrix format into long format, where each row represents one gene-sample pair.

It standardizes gene identifiers, converts numeric copy number alteration values into biological CNA status labels, handles missing or invalid values, removes exact duplicate rows, and prepares the dataset for integration with mutation, expression, and clinical data.

Main changes include:

- Converted CNA data from wide format into long format.
- Preserved `Hugo_Symbol` and `Entrez_Gene_Id` as fixed gene-level identifiers.
- Created `Sample_ID` to store sample identifiers after transformation.
- Stored numeric CNA values in `CNA_Value`.
- Converted `CNA_Value` into numeric format.
- Created `CNA_Status` to store biological CNA labels.
- Mapped numeric CNA values into biological labels:

  - `-2` = `deep_loss`
  - `-1` = `loss`
  - `0` = `neutral`
  - `1` = `gain`
  - `2` = `amplification`

- Assigned missing, invalid, or unexpected CNA values as `unknown`.
- Reordered columns into a clean structure:

  - `Hugo_Symbol`
  - `Entrez_Gene_Id`
  - `Sample_ID`
  - `CNA_Value`
  - `CNA_Status`

- Removed exact duplicate rows.
- Verified dataset size before and after duplicate removal.

This script converts RNA-seq gene expression data from wide format into long format, where each row represents a gene-sample pair.

Main changes include:

- Standardized `Hugo_Symbol`, `Entrez_Gene_Id`, and `Sample_ID`.
- Renamed the expression value column to `Expression`.
- Converted expression values into numeric format.
- Rounded expression values to two decimal places.
- Removed rows with zero expression values.
- Removed exact duplicate rows.
- Verified dataset size before and after duplicate removal.

## 1.4 Mutation Data Cleaning

| Item | Details |
|---|---|
| Input dataset | `Mutation(1).xlsx` |
| Output dataset | `Mutation.xlsx` |
| Script | `04_clean_mutations.py` |
| Stage | Cleaning |

This script processes mutation data by standardizing mutation annotations, selecting the most severe variant consequence for each mutation using VEP severity ranking, and calculating Variant Allele Frequency.

Main changes include:

- Renamed key fields to match the database schema.
- Renamed `Consequence` to `Primary_Consequence`.
- Renamed `IMPACT` to `Impact_Level`.
- Selected the most severe consequence using VEP severity ranking.
- Standardized mutation annotation fields.
- Converted read count fields into numeric format.
- Calculated Variant Allele Frequency using:

```text
VAF = t_alt_count / (t_ref_count + t_alt_count)
```

# 2. Dataset Validation

After the initial cleaning stage, all cleaned datasets were validated to confirm that they were structurally consistent and ready for harmonization.

This stage checks the presence of required identifiers such as `Sample_ID` and `Hugo_Symbol`, verifies that critical fields are not missing or empty, standardizes gene symbol formatting, and confirms that each file contains the required columns for downstream processing.

The HGNC reference file was also validated to ensure that it contains the fields needed for gene identifier mapping.

This step does not change the biological meaning of the data. It focuses on data integrity, identifier quality, and structural readiness.

| Item | Details |
|---|---|
| Input datasets | `Clinical&Sample.xlsx`, `long_expression.csv`, `Mutation.xlsx`, `cna_long.csv`, `hgnc_complete_set.txt` |
| Output datasets | Validated clinical, expression, mutation, CNA, and HGNC reference files |
| Script | `05_validator.py` |
| Stage | Validation |

# 3. Sample-Level Harmonization

This stage harmonizes the validated datasets at the sample level.

The script cleans and standardizes `Sample_ID` values across the clinical, expression, CNA, and mutation datasets. It then identifies the common set of samples shared across these datasets and filters each dataset to retain only matched samples.

This ensures that every retained sample has consistent representation across the required multi-omics data types. The resulting files are sample-matched and ready for gene-level harmonization.

| Item | Details |
|---|---|
| Input datasets | `Clinical&Sample.xlsx`, `long_expression.csv`, `Mutation.xlsx`, `cna_long.csv` |
| Output datasets | `clin_step1.xlsx`, `expr_step1.csv`, `cna_step1.csv`, `mut_step1.xlsx` |
| Script | `06_sample_harmonization.py` |
| Stage | Sample-level harmonization |

Figshare link: https://doi.org/10.6084/m9.figshare.32194617

# 4. Gene-Level Harmonization

This stage harmonizes the molecular datasets at the gene level.

The script standardizes `Hugo_Symbol` values across the expression, CNA, and mutation datasets. It then identifies the common set of genes shared across these molecular data types and filters each dataset to retain only those genes.

This step ensures that expression, CNA, and mutation records are based on a matched gene set, which supports reliable multi-omics integration and analysis.

# 5. HGNC-Based Gene Identifier Mapping

This stage standardizes gene identifiers using HGNC reference information.

The script maps `Hugo_Symbol` values to official HGNC-approved gene symbols and Entrez Gene IDs. It also uses alias symbols and previous gene names to resolve naming inconsistencies across the molecular datasets.

Unmapped or invalid gene entries are removed to ensure that all retained molecular records are linked to reliable standardized gene identifiers.

This step improves consistency across expression, CNA, and mutation datasets and prepares them for final integration.

# 6. Final Harmonization

This stage performs the final alignment across all processed datasets.

The script enforces both sample-level and gene-level consistency. It retains only samples shared across the clinical, expression, CNA, and mutation datasets. It also ensures that the molecular datasets contain only the common standardized genes shared across expression, CNA, and mutation data.

The output files from this stage represent the final harmonized multi-omics datasets. These files are ready for SQL table generation, database ingestion, graph database construction, and downstream analysis.

# 7. Final Proof Report

This stage generates a final validation and proof report for the completed pipeline.

The report summarizes key dataset metrics, including counts of patients, samples, genes, mutations, expression rows, CNA rows, and other omics records. It also checks sample-mutation relationships and confirms that the final datasets follow the logic needed for database population.

The report serves as a final data integrity check before SQL database construction and graph database modeling.
